# 已知问题

0.1 MVP 的已知限制。按影响排序，均为「可用但不完美」，无阻塞性缺陷。

## 编辑体验

1. **文字不会自动推开下方元素**。文字块高度随内容向下生长，若把正文加长，可能与下方段落重叠，需要手动挪动。模板初始文案已按中等长度预留间距。
2. **没有画布内联文字编辑**。双击文字元素只是聚焦右侧属性面板的输入框；不能直接在纸上打字。移动端因此多一步「开抽屉」。
3. **多选能力有限**。Shift 可多选（删除 / 图层操作生效），但属性面板只编辑第一个选中元素，不支持批量改属性。
4. **对齐 / 吸附未实现**。没有参考线磁吸、等距分布、元素间对齐工具；目前只有安全区虚框和网格可以目测对齐。
5. **没有旋转吸附**。Shift+旋转的 15° 步进依赖 Konva 内建行为，属性面板外的角度没有精度控制。
6. **无画布标尺**。显示的是缩放百分比而不是文档坐标刻度。

## 导出

7. **PDF 是单页**。内容就是当前纸张范围，不支持多页文档 / 跨页排版；超出纸张的部分在导出前会被 preflight 警告，导出时裁掉。
8. **PDF 内嵌位图**。文字与矢量在导出时按目标 dpi 重排渲染（非预览放大），但最终仍以高分辨率位图嵌入 PDF，而非 PDF 矢量文字——好处是版式 100% 一致、无字体缺失问题，代价是文件偏大（A4@300dpi 约 5–8MB）且文字不可选中检索。要做真矢量 PDF 需要换 SVG→PDF 管线，0.2 再评估。
9. **600dpi 在低配设备上较慢**。A4@600dpi 是 4960×7016 像素画布，渲染 + PNG 编码可能需要数秒；已加 9000px 边长与 72M 像素双重上限保护，超出会自动降档并在结果里提示。

## 数据

10. **撤销不含图片资源**。撤销会恢复元素（删除的图片元素能找回来），但「导入图片」这一步本身不在撤销栈里，资源池只增不减（保存时会清理未引用资源，属正常维护）。
11. **IndexedDB 容量依浏览器而定**。项目含大量图片时（每张压缩后最长边 1800px），总体积可能接近浏览器配额（通常数百 MB 起）；「项目」页签显示已用空间，超限时报错会以 toast 提示，编辑内容不丢（可立即导出 JSON 兜底）。
12. **无草稿箱跨浏览器迁移**。自动保存在浏览器 IndexedDB 里，换浏览器 / 清站点数据即失效；重要作品请用「导出项目 JSON」。

## 兼容

13. **字体依赖本机**。模板使用宋体 / 楷体 / 仿宋 / 黑体 / 等宽 / 西文衬线的系统字体栈，缺少对应字体的系统（如无中文字体的 Linux）会回退，导出对话框的 preflight 会列出缺失项。
14. **移动端以「能完成基本编辑」为界**。无捏合缩放以外的手势增强、无长按右键菜单；画布缩放用双指捏合或底部按钮。未在 iOS Safari 真机上回归过，桌面 Edge/Chrome 已实测。
15. **IndexedDB 被多标签页同时打开同一项目时**，后保存者覆盖先保存者，没有冲突合并（自动保存防抖 700ms，日常单人使用无感）。
